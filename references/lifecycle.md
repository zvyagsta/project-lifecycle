# Lifecycle decisions

## Setup

Define the project's purpose, success/acceptance criteria, participants by role, workstreams, current status, source location, output location, archive location, and who may approve or receive results. Reuse the existing directory layout when it is workable. Keep a short project overview and a current context for each active workstream; create another layer only when scale requires it.

## Material and result states

Incoming: `received → reviewed → linked to finding`. Store the original once. Record receipt date, source role, review state, and canonical path. A later workstream links to the canonical file.

Work: `draft → ready for review → approved/rejected → final result`. Keep evidence and uncertainty with internal work. Do not label a proposal as an agreed decision.

Delivery: `ready to deliver → delivered → acknowledged`, only where each state has evidence. A generated file does not establish delivery. If the channel or recipient is unknown, record that rather than guessing.

Archive: preserve the previous immutable version and point current navigation to the new one. Dated handoff notes are snapshots, not current status. Keep a short reason for replacement and link to the replacement.

## Context and decisions

The project overview answers: why this project exists, what is active, where to read next, and what rules apply broadly. A workstream context answers: what changed, what was decided and why, what is open, which materials matter, and the next concrete step. Record a decision with date, decision role, basis, and whether it replaces an earlier decision. Do not rewrite historical facts to match the current plan.

## Closure

For a workstream, record accepted output, acceptance evidence, unresolved follow-ups, current owner, and links to final and archived files. For project closure, additionally confirm project-level acceptance, delivery/handover, support or maintenance owner, open obligations, and a readable entry point for a future contributor. If any item is unconfirmed, describe the project as active or awaiting closure.
