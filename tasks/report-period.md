# report-period — report and infographic for other readers

**When:** a report for a manager or a team: «отчёт за день», «инфографика».

**Input:** evidence for the period, the current plan, the project's audience, design, accepted export formats and any explicit approval instructions.

**Steps**
1. Read [reports.md](../references/reports.md). Draft internally from evidence: progress against the plan, why the work mattered, what changed and the nearest planned actions. Keep source notes in the internal version.
2. Fill the report and infographic templates with source-backed text and show both as designed HTML previews. Check text and layout first; do not stop for separate text-draft approval. Follow [report-style.md](../references/report-style.md) for the design.
3. Obtain approval of the presented HTML version. Apply requested corrections narrowly, preserve accepted content and keep previous versions. Never mark an unapproved preview as approved.
4. Export the approved version to the project's accepted formats. Check the final layout and verify that the complete text matches the approved content.
5. Archive superseded and working materials without deletion. Keep the approved final documents, the latest approved period plan and the active period prompt in the main period folder as described in reports.md. Update context, check links and give clickable full-path links to the final files.

**Result:** HTML previews for review, then approved exported files and an organized period folder; delivery is a separate step.

**Done when:** the approved version has been exported and checked, previous versions are preserved, and current navigation works. Before approval, the result is a preview awaiting the user's decision.

**Do not:** demand text-only approval before HTML; invent progress; change accepted content beyond the requested correction; export unapproved changes; send or publish without authorization; shrink type to hide overflow.
